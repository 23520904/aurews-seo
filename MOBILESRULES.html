Rule 01 1

Viewport & Meta Foundation

Always set before anything else

Every news page must declare the viewport meta tag as the very first meta element in <head>. Without it, mobile browsers will render a shrunken desktop view. The initial-scale=1.0 prevents automatic zoom on iOS, and never set user-scalable=no — it breaks accessibility.

Required in <head>
<!-- REQUIRED: Must be first meta in <head> --> <meta charset="UTF-8"> <meta name="viewport" content="width=device-width, initial-scale=1.0"> <meta name="theme-color" content="#ffffff"> <!-- Open Graph for social sharing previews --> <meta property="og:type" content="article"> <meta property="og:image" content="[thumbnail-url]">
❌ Never do this Do not add user-scalable=no or maximum-scale=1. This fails WCAG 1.4.4 and Apple App Store review guidelines. Users with visual impairments rely on pinch-zoom.
Rule 02 2

Breakpoint System

Mobile-first, content-driven breakpoints

Design mobile-first: write base CSS for the smallest screen, then add min-width media queries as screens grow. Never use device-specific breakpoints — use content breakpoints. The layout should break when the content looks wrong, not at arbitrary device sizes.

Rule 03 3

Grid & Layout Architecture

Use CSS Grid. Avoid fixed-width columns.

News sites use a multi-column grid that collapses gracefully. The standard is a 12-column grid on desktop, 4-column on tablet, and a single-column stack on mobile. Use CSS Grid with named areas for page regions. Never use floats or position-based layouts.

Rule 04 4

Typography Scale

Fluid sizing · Minimum touch/read sizes

"Body text below 16px on mobile is a newsroom accessibility violation. Headlines must scale fluidly — never shrink below 20px."

Use clamp() for fluid typography that responds to viewport width without hard breakpoints. Body text must be at minimum 16px on all screens. Line length should stay between 45–75 characters per line for optimal readability.

Element Mobile Tablet Desktop CSS clamp()
H1 — Breaking Story 28px 36px 48–56px clamp(28px, 5vw, 56px)
H2 — Section Lead 22px 26px 32px clamp(22px, 3vw, 32px)
H3 — Card Title 18px 20px 22px clamp(18px, 2vw, 22px)
Body / Article 16px 17px 18px clamp(16px, 1.2vw, 18px)
Caption / Byline 12px 13px 14px clamp(12px, 1vw, 14px)
Label / Tag 10px 11px 12px clamp(10px, 0.8vw, 12px)
Fluid Typography System
:root { /* Fluid scale — no breakpoints needed */ --text-h1: clamp(28px, 5vw, 56px); --text-h2: clamp(22px, 3vw, 32px); --text-h3: clamp(18px, 2vw, 22px); --text-body: clamp(16px, 1.2vw, 18px); /* Line heights */ --lh-headline: 1.15; /* Tight for headlines */ --lh-body: 1.75; /* Airy for reading */ /* Max line length for readability */ --article-width: 68ch; /* 65–75ch is the sweet spot */ } .article-body { max-width: var(--article-width); font-size: var(--text-body); line-height: var(--lh-body); }
Rule 05 5

Images & Media

Responsive images · Aspect ratios · Lazy loading

Every image must use srcset and sizes attributes to serve correctly sized files to each device. The browser should never download a 2000px image on a 375px phone. Always define an aspect-ratio on image containers to prevent layout shift (CLS). Lazy-load everything below the fold.

Responsive Image Pattern
<!-- Standard news thumbnail --> <figure class="news-img"> <img src="story-800.jpg" srcset="story-400.jpg 400w, story-800.jpg 800w, story-1200.jpg 1200w" sizes="(max-width: 480px) 100vw, (max-width: 1024px) 50vw, 33vw" alt="[Descriptive caption]" loading="lazy" decoding="async" width="800" height="533" /> </figure> /* CSS — prevent layout shift with aspect-ratio */ .news-img { aspect-ratio: 16 / 9; /* hero: 16:9 */ overflow: hidden; } .news-img img { width: 100%; height: 100%; object-fit: cover; display: block; }
Image Type Aspect Ratio Min Width Format
Hero / Banner 16:9 800px WebP + JPEG fallback
Article Thumbnail 3:2 400px WebP + JPEG fallback
Card Image 4:3 320px WebP + JPEG fallback
Author Avatar 1:1 80px WebP + PNG fallback
Logo / SVG Icon — — SVG (inline preferred)
Rule 06 6

Navigation Patterns

Touch-friendly · Sticky header · Hamburger at mobile

The top navigation must be sticky on scroll. On mobile (<768px), collapse the nav into a hamburger menu. All touch targets must be minimum 44×44px (Apple HIG) or 48×48px (Material Design / WCAG 2.5.5). Category nav on desktop can use a horizontal scrollable strip on tablet/mobile.

Sticky Navigation CSS
.site-nav { position: sticky; top: 0; z-index: 1000; background: var(--color-bg); border-bottom: 1px solid var(--color-border); /* Performance: use transform for sticky shadow */ will-change: transform; } /* Touch target minimum */ .nav-item, .nav-btn { min-height: 44px; min-width: 44px; display: flex; align-items: center; padding: 0 12px; } /* Category nav scrolls horizontally on mobile */ .category-nav { display: flex; overflow-x: auto; -webkit-overflow-scrolling: touch; scrollbar-width: none; /* hide scrollbar */ gap: 4px; padding: 8px 16px; }
Rule 07 7

Spacing & Density

8px base grid · Consistent scale

All spacing must be multiples of 8px (or 4px for micro-spacing). Define a spacing scale as CSS custom properties and use them consistently. Mobile needs more generous padding than desktop because fingers are less precise than cursors. Side margins on mobile: minimum 16px.

Spacing Scale
:root { --space-1: 4px; --space-2: 8px; --space-3: 12px; --space-4: 16px; /* min side margin on mobile */ --space-5: 24px; --space-6: 32px; --space-7: 40px; --space-8: 48px; --space-9: 64px; --space-10: 96px; /* Section padding: more breathable on desktop */ --section-pad-mobile: var(--space-5); /* 24px */ --section-pad-desktop: var(--space-8); /* 48px */ }
Rule 08 8

Performance Targets

Core Web Vitals · Mobile-first budgets

News sites lose 53% of mobile users if a page takes longer than 3 seconds to load (Google). You must meet Core Web Vitals thresholds on mobile. Defer non-critical JS, preload hero images, and serve next-gen formats.

Metric Good Needs Work Poor
LCP (Largest Contentful Paint) < 2.5s 2.5–4s > 4s
CLS (Cumulative Layout Shift) < 0.1 0.1–0.25 > 0.25
INP (Interaction to Next Paint) < 200ms 200–500ms > 500ms
TTFB (Time to First Byte) < 800ms 800ms–1.8s > 1.8s
Page Weight (Mobile) < 1MB 1–3MB > 3MB
Preload Hero Image + Defer Fonts
<!-- Preload above-fold hero image --> <link rel="preload" as="image" href="hero.webp" imagesrcset="hero-400.webp 400w, hero-800.webp 800w" imagesizes="100vw"> <!-- Defer non-critical scripts --> <script src="analytics.js" defer></script> <script src="comments.js" defer></script> <!-- Fonts: display=swap prevents invisible text --> <link href="fonts.googleapis.com/...&display=swap" rel="stylesheet">
Rule 09 9

Accessibility (WCAG 2.1 AA)

Mandatory — not optional

Global news outlets must meet WCAG 2.1 Level AA as a legal requirement in the EU, UK, and US. This covers contrast ratios, keyboard navigation, screen reader compatibility, and focus indicators. On mobile, additionally ensure content reflows at 320px width without horizontal scroll (WCAG 1.4.10).

  • Colour contrast: minimum 4.5:1 for body text, 3:1 for large text and UI components
  • All interactive elements focusable via keyboard; visible focus ring (2px solid, high contrast)
  • Semantic HTML: use <article>, <nav>, <main>, <aside>, <header>, <footer>
  • Every image has a meaningful alt attribute; decorative images get alt=""
  • Skip-to-content link as first focusable element on every page
  • Page fully operable at 200% browser zoom without horizontal scroll (WCAG 1.4.4)
  • ARIA live regions for breaking news banners: aria-live="polite"
  • Never use colour alone to convey meaning (e.g. "red = breaking news" with no text label)
  • Never auto-play video or audio without controls
  • Never use <div> or <span> for buttons or links
  • Never set outline: none without providing an alternative focus style
Rule 10 10

Dark Mode Support

prefers-color-scheme · CSS variables

Major news apps (NYT, BBC, Reuters) all support dark mode. Use CSS custom properties for all colour values — this makes dark mode a one-declaration override. Images should use <picture> with a dark-mode alternative when needed. Never use filter: invert() on images.

Dark Mode via CSS Variables
:root { --color-bg: #ffffff; --color-surface: #f5f5f5; --color-text: #111111; --color-text-2: #555555; --color-border: #e0e0e0; --color-accent: #c0392b; /* breaking red */ } @media (prefers-color-scheme: dark) { :root { --color-bg: #121212; --color-surface: #1e1e1e; --color-text: #e8e8e8; --color-text-2: #aaaaaa; --color-border: #333333; --color-accent: #e05555; } }
Rule 11 11

Article Page Structure

Semantic HTML · Reading experience

The article reading experience is the core product of a news site. Use the proper semantic structure so screen readers, RSS parsers, and search engines all understand the content hierarchy correctly.

Semantic Article Template
<article itemscope itemtype="https://schema.org/NewsArticle"> <header class="article-header"> <span class="article-tag">Politics</span> <h1 itemprop="headline">Article Headline</h1> <p class="standfirst">Deck / standfirst text</p> <div class="byline"> <address itemprop="author">By Jane Smith</address> <time itemprop="datePublished" datetime="2025-05-12T08:00:00Z"> 12 May 2025 </time> </div> </header> <figure class="article-hero"> <img src="..." alt="..." loading="eager"> <figcaption itemprop="description">Caption</figcaption> </figure> <div class="article-body" itemprop="articleBody"> <!-- Paragraphs, pull quotes, embeds --> </div> </article>
Rule 12 12

Colour System

Brand · Breaking · Category · Status

News sites use colour purposefully and sparingly. Red is universally reserved for "breaking" and urgent content. Category colours help users navigate but must never rely solely on hue. Define all colours as tokens, not inline hex values.

Token Purpose Typical Value Contrast Req.
--color-breaking Breaking news label #c0392b AA on white
--color-live Live blog indicator #e74c3c (animated) AA on white
--color-opinion Opinion / comment #2980b9 AA on white
--color-feature Long-form / magazine #8e44ad AA on white
--color-sponsored Sponsored / ad content #f0a500 Must have label
--color-success Subscribed / saved #27ae60 AA on white
⚠ Sponsored Content Sponsored content MUST be visually distinct and labelled with text ("Sponsored" or "Advertisement"), never only distinguished by colour. This is a legal requirement in most markets (FTC, ASA, ARPP).
Rule 13 13

Forms, Modals & Paywalls

Fullscreen on mobile · No viewport jump

Subscription modals and newsletter forms must display as a fullscreen overlay on screens below 768px — never as a small centred popup (which is unreadable on mobile). Prevent body scroll when a modal is open. Email inputs must use type="email" to trigger the correct keyboard. Inputs must be minimum 48px tall.

Modal Body Lock Pattern
/* Prevent body scroll when modal open */ body.modal-open { overflow: hidden; position: fixed; width: 100%; /* Prevent iOS scroll position jump */ top: calc(var(--scroll-y) * -1px); } .modal { position: fixed; inset: 0; z-index: 9999; display: flex; flex-direction: column; } /* Full-screen on mobile */ @media (max-width: 767px) { .modal-box { width: 100%; min-height: 100%; border-radius: 0; padding: 24px 20px; } } /* Touch-friendly inputs */ input[type="email"], input[type="text"], select { min-height: 48px; font-size: 16px; /* Prevents iOS auto-zoom */ padding: 12px 14px; }
📱 iOS Auto-Zoom Fix Always set font-size: 16px on inputs. iOS Safari automatically zooms in when an input has font-size < 16px, which breaks the layout and disorients users.
Rule 14 14

Pre-Launch Checklist

Test on real devices before every release

  • Test on real iOS Safari (iPhone SE / 375px) and Android Chrome (360px) — emulators miss rendering bugs
  • Run Lighthouse audit: target Performance ≥ 80, Accessibility ≥ 95 on mobile
  • Validate HTML with W3C Validator — semantic errors break screen readers
  • Test with keyboard-only navigation: tab through every interactive element
  • Test with VoiceOver (iOS) or TalkBack (Android) for screen reader flow
  • Check all images render without layout shift (CLS score below 0.1)
  • Verify article text is readable at 200% zoom without horizontal scrolling
  • Validate structured data with Google's Rich Results Test tool
  • Test dark mode on both iOS and Android system settings
  • Verify no horizontal overflow on any screen from 320px to 1440px
