Prisma + SupabaseConnection Pool
Database — Prisma Schema & Connection Pooling
Serverless functions open a new DB connection per invocation. Without pooling, you hit Postgres connection limits and get too many clients 500 errors. Use PgBouncer via Supabase's pgbouncer=true param and the singleton Prisma client pattern.
prisma/schema.prisma — datasource block
datasource db { provider = "postgresql" url = env("DATABASE_URL") // PgBouncer URL — used by app functions directUrl = env("DIRECT_URL") // Direct URL — used by prisma migrate } generator client { provider = "prisma-client-js" binaryTargets = ["native", "rhel-openssl-3.0.x"] // Required for Netlify Linux env }

Step-by-Step: First Deploy to Netlify
1
Install Netlify Next.js plugin
Run npm i -D @netlify/plugin-nextjs. This is what enables full App Router, Server Actions, ISR, and Edge Middleware support on Netlify. Without it, Server Actions silently fail and ISR doesn't work.
2
Commit netlify.toml + .nvmrc to repo root
Both files must exist at the root. .nvmrc containing 20 pins Node 20. Without it Netlify may default to Node 18 or 21, causing build failures.
3
Connect repo in Netlify Dashboard
Dashboard → Add new site → Import from Git. Choose GitHub/GitLab. Netlify will auto-detect Next.js and the netlify.toml settings. Do not override build command or publish directory in the UI — the TOML takes precedence.
4
Add all environment variables
Site configuration → Environment variables → Add all variables from the table above. Scope DATABASE_URL to Production + Preview. Scope NEXTAUTH_URL to Production only (each preview deploy gets its own URL via URL env var automatically).
5
Run Prisma migration against production DB
Run DATABASE_URL="..." npx prisma migrate deploy locally or via a one-off Netlify Function. Never run prisma db push against production (no migration history). The postinstall script in package.json runs prisma generate automatically at build time.
6
Trigger deploy & verify
Push to main. Monitor build log. Check for zero TS errors, zero ESLint errors, zero Prisma warnings. Visit /api/health — should return {"status":"ok"}. Check Netlify Functions log tab for any cold-start errors.
7
Configure custom domain + HTTPS
Domain management → Add custom domain. Netlify auto-provisions Let's Encrypt TLS. Update NEXTAUTH_URL and NEXT_PUBLIC_SITE_URL env vars to the custom domain. Redeploy.
§ 09 — Zero Errors · Zero Warnings · No 500s
Production Hardening Checklist
Every item below prevents a class of runtime errors, TypeScript warnings, or internal server failures. Treat each as a required fix, not an optional improvement.

Common 500 Causes & Fixes

Error / WarningRoot CauseFix
Error: too many clients Prisma opens a new connection per invocation in serverless. Hits Postgres max_connections. Use PgBouncer URL with ?pgbouncer=true&connection_limit=1. Use singleton Prisma client pattern (lib/prisma.ts shown above).
NEXTAUTH_URL mismatch NEXTAUTH_URL set to dev URL in production, or missing. NextAuth throws a 500 on any auth callback. Set NEXTAUTH_URL to exact production URL in Netlify env vars. For preview deploys, use NEXTAUTH_URL=$URL (Netlify injects $URL automatically per deploy).
prisma: binaryTargets error Prisma native binaries compiled for wrong architecture. Netlify runs on rhel-openssl-3.0.x. Add binaryTargets = ["native", "rhel-openssl-3.0.x"] to schema.prisma generator block.
next/image: hostname not allowed An external image URL's hostname is not listed in next.config.js remotePatterns. Returns 400. Add every external image domain to images.remotePatterns in next.config.js. Cover Cloudinary, Unsplash, GitHub avatars etc.
Server Action: CSRF failure Missing NEXTAUTH_SECRET or NEXTAUTH_URL causes CSRF token mismatch on Server Action POST. Returns 403 or 500. Ensure both env vars are set. Server Actions require exact Origin header match with NEXTAUTH_URL.
punycode DeprecationWarning Node 22 / some Node 20 sub-versions deprecate built-in punycode. Appears in build logs as a warning. Add to webpack config: config.ignoreWarnings = [{ module: /node_modules\/punycode/ }].
Dynamic server usage: cookies() Calling cookies() or headers() in a statically-rendered route causes a build error in Next 14. Add export const dynamic = 'force-dynamic' to any route that reads cookies/headers at runtime (e.g. dashboard layout).
useSearchParams() + Suspense useSearchParams() must be wrapped in <Suspense> in App Router. Missing boundary causes build-time error. Wrap every component using useSearchParams() in a <Suspense fallback={...}> parent. Create a wrapper client component if needed.
Unhandled promise rejection API routes / Server Actions without try/catch crash the function, returning a bare 500 with no useful message. All async route handlers and Server Actions must use try/catch with typed error responses. See error handler pattern below.
getServerSession() returns null Forgetting to pass authOptions to getServerSession() in App Router. Returns null even if user is logged in. Always use getServerSession(authOptions) — pass your authOptions object explicitly. Export it from lib/auth.ts.
Missing error.tsx / not-found.tsx Unhandled thrown errors and 404s show a generic Netlify error page instead of your branded UI. Create app/error.tsx (client component with 'use client') and app/not-found.tsx. Both required at root level.
ESLint: no-unused-vars warn Default ESLint config treats unused vars as warnings that pollute build output. In .eslintrc.json: set "no-unused-vars": ["error", { "argsIgnorePattern": "^_" }]. Prefix intentionally unused params with _.
Required PatternAll API Routes
Standardized API Error Handler
Use this pattern in every Route Handler. Catches all thrown errors, logs them server-side, and returns a consistent JSON response — never a bare 500 with no body.
lib/api-response.ts — response helpers
import { NextResponse } from 'next/server' export function ok<T>(data: T, status = 200) { return NextResponse.json({ success: true, data }, { status }) } export function err(message: string, status = 500, details?: unknown) { if (process.env.NODE_ENV !== 'production') { console.error(`[API ${status}]`, message, details) } return NextResponse.json({ success: false, error: message }, { status }) } export function withErrorHandler( handler: (...args: unknown[]) => Promise<NextResponse> ) { return async (...args: unknown[]) => { try { return await handler(...args) } catch (e) { console.error('[Unhandled API Error]', e) return err('Internal server error', 500, e) } } }
app/api/posts/route.ts — usage example
import { ok, err, withErrorHandler } from '@/lib/api-response' import { prisma } from '@/lib/prisma' import { getServerSession } from 'next-auth' import { authOptions } from '@/lib/auth' // always pass authOptions! export const GET = withErrorHandler(async (req: Request) => { const { searchParams } = new URL(req.url) const limit = Number(searchParams.get('limit')) || 12 const posts = await prisma.post.findMany({ where: { status: 'PUBLISHED', deletedAt: null }, take: limit, orderBy: { createdAt: 'desc' }, }) return ok(posts) }) export const POST = withErrorHandler(async (req: Request) => { const session = await getServerSession(authOptions) if (!session) return err('Unauthorized', 401) const body = await req.json() // validate body with zod here... const post = await prisma.post.create({ data: { ...body, authorId: session.user.id } }) return ok(post, 201) })

  • CHECK Every getServerSession() call passes authOptions as argument.
  • CHECK All external image hostnames are in next.config.js remotePatterns.
  • CHECK prisma/schema.prisma has binaryTargets = ["native", "rhel-openssl-3.0.x"].
  • CHECK DATABASE_URL uses PgBouncer port (6543) with ?pgbouncer=true&connection_limit=1.
  • CHECK DIRECT_URL uses direct port (5432) — different from DATABASE_URL.
  • CHECK NEXTAUTH_URL exactly matches production domain (no trailing slash).
  • CHECK NEXTAUTH_SECRET is set and ≥ 32 chars.
  • CHECK .nvmrc contains 20 and netlify.toml has NODE_VERSION = "20".
  • CHECK @netlify/plugin-nextjs is listed in netlify.toml [[plugins]] and installed as dev dep.
  • CHECK All API route handlers are wrapped with withErrorHandler or have explicit try/catch.
  • CHECK /api/health returns {"status":"ok"} locally.
  • AVOID console.log in production server code — use console.error only (prevents log noise that can mask real errors).
  • NEVER Commit .env.local or any file with real secrets. Verify .gitignore includes .env*.
