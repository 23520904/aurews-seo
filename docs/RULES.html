§ 01 — The Language Mandate

Strict TypeScript Only

There is no compromise or "mix" between JavaScript and TypeScript. For SEO optimization, server uptime must be flawless. Search engine crawlers severely penalize sites that return 500 errors or crash during indexing. Therefore, robust type-safety is an indirect but critical SEO requirement.

MANDATE: NO JAVASCRIPT ALLOWED (.js / .jsx)
All code generated by the agent MUST use strict TypeScript (.ts, .tsx). Using any is strictly forbidden. Define explicit interfaces and types for every data structure, API response, and component prop.
Strict RuleSEO + Uptime
Why TypeScript for SEO?
TypeScript compiles to JavaScript, meaning the browser and crawler see the exact same output. However, unhandled runtime errors in vanilla JS cause SSR (Server-Side Rendering) failures, resulting in blank pages or 500 status codes. Googlebot immediately drops indexing scores for 500 errors. Strict typing guarantees data contracts and prevents these fatal SSR crashes.
  • Use interface or type for all Component Props.
  • Type all API responses explicitly.
  • Configure tsconfig.json with "strict": true.
  • Never use @ts-ignore. Fix the underlying type issue.
§ 02 — SEO Technical Specifications
App Router Metadata
Use Next.js generateMetadata() for dynamic pages. Always include title, description, openGraph, and canonical URLs. Never inject meta tags via client-side effects.
JSON-LD Schema
Inject structured data via <script type="application/ld+json">. Use standard schemas like Article, WebSite, BreadcrumbList, and FAQPage.
Semantic HTML
Strict hierarchy: Only one <h1> per page. Use <main>, <article>, <aside>, and <nav> appropriately. Avoid generic <div> soup.
Core Web Vitals: LCP
The largest contentful paint (hero image) MUST use next/image with the priority={true} attribute to inject a preload link into the document head.
Dynamic Sitemaps
Use App Router's sitemap.ts and robots.txt files to auto-generate indexable maps of all database-driven dynamic routes.
SSR vs SSG
Favor Static Site Generation (SSG) with Incremental Static Regeneration (ISR) using revalidate over pure Server-Side Rendering (SSR) for faster TTFB (Time to First Byte).
Required Pattern
Metadata Implementation
app/blog/[slug]/page.tsx
import { Metadata } from 'next' interface PageProps { params: { slug: string } } export async function generateMetadata({ params }: PageProps): Promise<Metadata> { const post = await fetchPost(params.slug) return { title: post.title, description: post.excerpt, alternates: { canonical: `https://yoursite.com/blog/${params.slug}` }, openGraph: { title: post.title, images: [post.coverImage] } } }
§ 03 — Netlify Configuration Directive
Platform Specifics
Code MUST be written to support Netlify's serverless/edge environment. This means being aware of cold starts, database connection pooling, and strict build configurations.
next.config.jsMandatory
Netlify Bundling Rules
For Netlify to correctly bundle a Next.js App Router project into serverless functions, the output mode must be explicitly set.
next.config.js
/** @type {import('next').NextConfig} */ const nextConfig = { // REQUIRED: Netlify needs standalone output to trace dependencies output: 'standalone', images: { // REQUIRED: Explicitly define remote domains for Next Image remotePatterns: [ { protocol: 'https', hostname: 'images.unsplash.com' } ] } } export default nextConfig

§ 04 — Agent Checklist & Anti-Patterns
Validation
Code Generation Checklist
Before outputting code, the AI agent MUST internally verify these conditions are met:
  • CHECK Is the file .ts or .tsx? (No .js).
  • CHECK Are all function parameters and return types explicitly defined?
  • CHECK If it is a Next.js Page, does it export generateMetadata() for SEO?
  • CHECK Does the API route have a try/catch block to prevent unhandled 500s?
  • CHECK If rendering an image, is next/image used with exact width, height, and an alt tag for accessibility/SEO?
  • CHECK Are client components clearly marked with "use client" at the very top?
  • NEVER Use any. Provide a proper Type or Interface.
  • NEVER Leave empty catch blocks. Always log the error server-side and return a structured JSON error response.
