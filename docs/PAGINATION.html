§ 01 — Overview

Pagination Mechanisms

Design Principle — URL-First State
All pagination state lives in the URL (?page=3, ?cursor=abc). This ensures deep-linking, browser Back/Forward, and SSR work correctly. Never use component-local state as the source of truth for page position in routes the user can share.

§ 02 — Cursor Pagination & Load More Button
Used on: /latest · /category/[slug]

Cursor pagination uses a stable pointer (the id or createdAt of the last item seen) to fetch the next page. No items skip or duplicate when new posts are published mid-session.

How a cursor works
The API returns a nextCursor — the opaque ID of the last item in the current page. The client appends ?cursor=nextCursor to fetch the next batch. When nextCursor === null, there are no more results and the button is hidden.

Componentapp/latest/page.tsx
Server Page + Client Load More
The page component fetches the first page server-side (SSR). The client <LoadMore> component handles subsequent fetches without a full page reload.
app/latest/page.tsx — server component
import { LoadMore } from '@/components/LoadMore'
import { PostCard  } from '@/components/PostCard'
import { prisma    } from '@/lib/prisma'

const PAGE_SIZE = 20

export default async function LatestPage() {
  // Server-side: fetch first page
  const posts = await prisma.post.findMany({
    where:   { status: 'PUBLISHED', deletedAt: null },
    take:    PAGE_SIZE + 1,   // fetch +1 to detect hasMore
    orderBy: { createdAt: 'desc' },
    include: { author: true, category: true },
  })

  const hasMore    = posts.length > PAGE_SIZE
  const items      = hasMore ? posts.slice(0, PAGE_SIZE) : posts
  const nextCursor = hasMore ? items[items.length - 1].id : null

  return (
    <main>
      <h1>Latest Stories</h1>
      <ul>
        {items.map(post => (
          <PostCard key={post.id} post={post} />
        ))}
      </ul>
      /* Client component handles all subsequent loads */
      <LoadMore
        initialCursor={nextCursor}
        endpoint="/api/posts/latest"
        pageSize={10}
      />
    </main>
  )
}
components/LoadMore.tsx — client component
'use client'
import { useState, useTransition } from 'react'
import { PostCard } from './PostCard'

type Props = {
  initialCursor: string | null
  endpoint:      string
  pageSize:      number
}

export function LoadMore({ initialCursor, endpoint, pageSize }: Props) {
  const [posts,  setPosts ] = useState<Post[]>([])
  const [cursor, setCursor] = useState(initialCursor)
  const [isPending, startTransition] = useTransition()

  if (!cursor) return (
    <p className="all-loaded-msg">All stories loaded</p>
  )

  async function fetchMore() {
    startTransition(async () => {
      const res  = await fetch(
        `${endpoint}?cursor=${cursor}&limit=${pageSize}`
      )
      if (!res.ok) throw new Error('fetch failed')

      const { data } = await res.json()
      setPosts(prev => [...prev, ...data.posts])
      setCursor(data.nextCursor)    // null when exhausted
    })
  }

  return (
    <>
      {posts.map(post => <PostCard key={post.id} post={post} />)}

      {cursor && (
        <button
          onClick={fetchMore}
          disabled={isPending}
          className={`btn-load-more ${isPending ? 'loading' : ''}`}
        >
          {isPending ? '' : 'Load More Stories'}
        </button>
      )}
    </>
  )
}
APIapp/api/posts/latest/route.ts
Cursor API Endpoint
The GET /api/posts/latest endpoint accepts a cursor and limit query param and returns a consistent paginated response envelope.
app/api/posts/latest/route.ts
import { ok, err, withErrorHandler } from '@/lib/api-response'
import { prisma } from '@/lib/prisma'

export const GET = withErrorHandler(async (req: Request) => {
  const { searchParams } = new URL(req.url)
  const cursor = searchParams.get('cursor')        // optional
  const limit  = Math.min(Number(searchParams.get('limit')) || 10, 50)

  const posts = await prisma.post.findMany({
    take:    limit + 1,              // overfetch by 1 to detect hasMore
    skip:    cursor ? 1 : 0,       // skip cursor item itself
    cursor:  cursor ? { id: cursor } : undefined,
    where:   { status: 'PUBLISHED', deletedAt: null },
    orderBy: { createdAt: 'desc' },
    include: { author: true, category: true },
  })

  const hasMore    = posts.length > limit
  const items      = hasMore ? posts.slice(0, limit) : posts
  const nextCursor = hasMore ? items[items.length - 1].id : null

  return ok({
    posts:      items,
    nextCursor,             // null = no more pages
    count:      items.length,
  })
})
Response envelope shape
{

  "data": {
    "posts":      [...],        // array of post objects
    "nextCursor": "post_cuid_xyz",  // or null if end of feed
    "count":      10
  }
}
§ 03 — Numeric Page Pagination
Used on: /search · /admin/posts · /dashboard/my-posts

Numeric (offset) pagination shows page numbers and allows jumping to any page. Best for admin tables and search results where users want a known position. State lives in the URL as ?page=N.

Offset tradeoff
Offset pagination (LIMIT 25 OFFSET 50) is simple but O(n) — the DB scans all skipped rows. For large datasets (>10k posts) in admin views, this is acceptable. Never use offset on public feeds where N can grow unboundedly.

Componentcomponents/Paginator.tsx
Numeric Paginator Component
A reusable Server-Component-compatible paginator that generates URL-based page links. No client JS needed for basic navigation — links are standard <a> tags with ?page=N.
components/Paginator.tsx
import Link from 'next/link'

type Props = {
  currentPage:  number
  totalPages:   number
  basePath:     string          // e.g. "/search?q=bitcoin"
  pageParam?:   string          // default "page"
}

function buildPages(current: number, total: number): (number | '…')[] {
  if (total <= 7) return Array.from({ length: total }, (_, i) => i + 1)

  const pages: (number | '…')[] = [1]

  if (current > 3) pages.push('…')

  const start = Math.max(2, current - 1)
  const end   = Math.min(total - 1, current + 1)
  for (let i = start; i <= end; i++) pages.push(i)

  if (current < total - 2) pages.push('…')
  pages.push(total)
  return pages
}

export function Paginator({ currentPage, totalPages, basePath, pageParam = 'page' }: Props) {
  const href = (p: number) => `${basePath}&${pageParam}=${p}`
  const pages = buildPages(currentPage, totalPages)

  return (
    <nav aria-label="Pagination" className="pg-bar">
      <Link
        href={href(currentPage - 1)}
        className=`pg-btn pg-arrow ${currentPage <= 1 ? 'disabled' : ''}`
        aria-disabled={currentPage <= 1}
      >← Prev</Link>

      {pages.map((p, i) =>
        p === '…'
          ? <span key={i} className="pg-btn pg-dots">…</span>
          : <Link
              key={p}
              href={href(p)}
              className={`pg-btn ${p === currentPage ? 'pg-active' : ''}`}
              aria-current={p === currentPage ? 'page' : undefined}
            >{p}</Link>
      )}

      <Link
        href={href(currentPage + 1)}
        className=`pg-btn pg-arrow ${currentPage >= totalPages ? 'disabled' : ''}`
        aria-disabled={currentPage >= totalPages}
      >Next →</Link>
    </nav>
  )
}
app/search/page.tsx — reading page from searchParams
const PAGE_SIZE = 10

export default async function SearchPage({
  searchParams
}: {
  searchParams: { q?: string; page?: string }
}) {
  const query = searchParams.q ?? ''
  const page  = Math.max(1, Number(searchParams.page) || 1)
  const skip  = (page - 1) * PAGE_SIZE

  const [posts, total] = await Promise.all([
    prisma.post.findMany({
      where: {
        status: 'PUBLISHED',
        deletedAt: null,
        OR: [
          { title:   { contains: query, mode: 'insensitive' } },
          { excerpt: { contains: query, mode: 'insensitive' } },
        ],
      },
      skip,
      take: PAGE_SIZE,
      orderBy: { createdAt: 'desc' },
    }),
    prisma.post.count({ where: { /* same where */ } }),
  ])

  const totalPages = Math.ceil(total / PAGE_SIZE)

  return (
    <>
      <PostList posts={posts} />
      <Paginator
        currentPage={page}
        totalPages={totalPages}
        basePath={`/search?q=${encodeURIComponent(query)}`}
      />
    </>
  )
}
§ 04 — Infinite Scroll (Optional / Mobile)
Optional pattern for mobile /latest feeds

Infinite scroll auto-triggers the next page when the user scrolls within ~300px of the bottom. Uses IntersectionObserver for zero-jank detection. Built on top of the same cursor API — no new backend needed.

Caution — editorial UX
Infinite scroll is not the default for NEWSROOM. News readers scan headlines; they should control when they load more. Use Load More (§02) for all public feeds. Infinite scroll is only appropriate inside dedicated mobile app-like surfaces where content consumption, not headline scanning, is the goal.

Componentcomponents/InfiniteList.tsx
IntersectionObserver Hook
A sentinel <div ref=sentinelRef> at the bottom of the list is watched by an IntersectionObserver. When it enters the viewport, the next page is fetched automatically. Reuses the same cursor API as Load More.
hooks/useInfiniteScroll.ts
'use client'
import { useEffect, useRef, useState, useCallback } from 'react'

export function useInfiniteScroll<T>(
  endpoint: string,
  initialCursor: string | null,
  pageSize = 10
) {
  const [items,   setItems  ] = useState<T[]>([])
  const [cursor,  setCursor ] = useState(initialCursor)
  const [loading, setLoading] = useState(false)
  const sentinelRef = useRef<HTMLDivElement>(null)

  const fetchMore = useCallback(async () => {
    if (loading || !cursor) return
    setLoading(true)
    try {
      const res  = await fetch(`${endpoint}?cursor=${cursor}&limit=${pageSize}`)
      const json = await res.json()
      setItems(prev => [...prev, ...json.data.posts])
      setCursor(json.data.nextCursor)
    } finally { setLoading(false) }
  }, [cursor, loading, endpoint, pageSize])

  // Attach IntersectionObserver to sentinel element
  useEffect(() => {
    if (!sentinelRef.current) return
    const observer = new IntersectionObserver(
      ([entry]) => { if (entry.isIntersecting) fetchMore() },
      { rootMargin: '300px' }   // trigger 300px before visible
    )
    observer.observe(sentinelRef.current)
    return () => observer.disconnect()
  }, [fetchMore])

  return { items, loading, hasMore: !!cursor, sentinelRef }
}
§ 05 — Filter Chips & Sort Controls

Filters and sorting always reset pagination to page 1 / clear the cursor, and update the URL. The full filter+sort state lives in the URL so it is shareable and works with browser history.

Rule — Always reset pagination on filter change
When a user changes category, sort order, or any filter, remove page and cursor from the URL and restart from the beginning. Never paginate a filtered result mid-stream. The new router.push() call should omit the previous pagination param.
PatternURL State Sync
Filter + Sort → URL Sync Pattern
Both client-side filter chips and sort dropdowns update the URL with router.push(), never component-local state. This drives a server re-render with the new params.
components/FilterBar.tsx — client component
'use client'
import { useRouter, useSearchParams, usePathname } from 'next/navigation'

const CATEGORIES = ['all', 'business', 'tech-innovation', 'ai', 'money-markets', 'politics']
const SORTS      = ['newest', 'oldest', 'popular'] as const

export function FilterBar() {
  const router       = useRouter()
  const pathname     = usePathname()
  const searchParams = useSearchParams()

  const currentCat  = searchParams.get('category') ?? 'all'
  const currentSort = searchParams.get('sort')     ?? 'newest'

  function update(key: string, value: string) {
    const params = new URLSearchParams(searchParams.toString())
    params.set(key, value)
    params.delete('page')    // ← reset pagination
    params.delete('cursor')  // ← reset cursor
    router.push(`${pathname}?${params.toString()}`)
  }

  return (
    <div>
      </* Category chips */>
      <div className="chips">
        {CATEGORIES.map(cat => (
          <button
            key={cat}
            className={`chip ${cat === currentCat ? 'active' : ''}`}
            onClick={() => update('category', cat)}
          >
            {cat === 'all' ? 'All' : cat}
          </button>
        ))}
      </div>

      </* Sort options */>
      <div className="sort-options">
        {SORTS.map(s => (
          <button
            key={s}
            className={`sort-opt ${s === currentSort ? 'active' : ''}`}
            onClick={() => update('sort', s)}
          >{s}</button>
        ))}
      </div>
    </div>
  )
}

§ 07 — Common Pitfalls & Fixes
Mistake Consequence Fix
Offset on real-time public feed New posts shift offsets → user sees duplicate posts or skipped stories between pages Use cursor pagination on all public feeds. Only use offset in admin/search where insertions during browsing are rare
Forgetting +1 overfetch Cannot determine if there are more results without an extra count() query Always take: limit + 1 and check posts.length > limit to set hasMore without a separate count query
No Suspense on useSearchParams() Build fails: "useSearchParams() should be wrapped in a suspense boundary" Wrap FilterBar (or any component calling useSearchParams) in <Suspense fallback={…}>
Not resetting cursor on filter change User changes category filter; Load More still fetches from old cursor offset — wrong category Always call params.delete('cursor') and params.delete('page') before router.push on any filter change
Mutable page state in component Browser Back button doesn't restore the previous page; user loses scroll position Always store pagination in URL (?page=, ?cursor=). URL is the source of truth for page position
No loading state on Load More User taps button twice → duplicate API calls → duplicate posts inserted Disable the button while isPending is true. useTransition handles this automatically; or use a manual isLoading flag with early return
Cursor on search / noindex content Search results indexed by cursor URLs — meaningless to crawlers, wastes crawl budget Search and admin pages use noindex. Use offset+page on these routes regardless, since SEO and result stability are not concerns
Uncapped limit param GET /api/posts?limit=99999 — a single request dumps the entire database const limit = Math.min(Number(searchParams.get('limit')) || 10, 50) — always clamp to a sane max
Pre-Deploy
Pagination Pre-Deploy Checklist
  • CHECK All public feed routes use cursor pagination, not offset.
  • CHECK All cursor API handlers use take: limit + 1 overfetch pattern.
  • CHECK limit is clamped: Math.min(Number(x) || default, max) in every API handler.
  • CHECK FilterBar and all useSearchParams() callers are wrapped in <Suspense>.
  • CHECK Filter/sort changes delete cursor and page from URL before push.
  • CHECK Load More button is disabled while isPending.
  • CHECK When nextCursor === null, button is hidden or shows "All stories loaded".
  • CHECK Paginator href links use aria-current="page" for accessibility.
  • WARN Numeric paginator on public routes: verify the page has a noindex tag if deep pages should not be indexed.
  • NEVER Store pagination state in React useState as the sole source of truth — it breaks browser history.
  • NEVER Use offset pagination on /latest or /category/[slug] — new post insertions will cause skips.
