§ 01 — Overview

Sitemap & Robots.txt for Google 2026

In 2026, Google's crawler reads both files on every deploy cycle. A correctly structured sitemap speeds up index coverage for new articles; a correctly scoped robots.txt prevents dilution of crawl budget and keeps admin/auth routes out of search results. This guide covers both, end-to-end, for a Next.js App Router project on Netlify.

Why app/sitemap.ts over static sitemap.xml?
A static sitemap.xml in /public quickly becomes stale. Next.js App Router's app/sitemap.ts generates the XML at request time (or at build time with ISR), pulling live slugs from the database. Every published article is always in the sitemap within seconds of publication.
2026 Google change: IndexNow + sitemap ping deprecated
Google has soft-deprecated the ?sitemap= ping URL. Use IndexNow (Bing/Yandex/Google unified protocol) via webhook on publish, or rely on Search Console's auto-discovery. The sitemap URL in robots.txt remains the most reliable discovery signal.

app/sitemap.ts — Full Implementation
Place this file at app/sitemap.ts. Next.js automatically serves it at /sitemap.xml. No redirect needed. Returns a typed MetadataRoute.Sitemap array that Next.js converts to valid XML.
app/sitemap.ts
import { MetadataRoute } from 'next' import { prisma } from '@/lib/prisma' // Force dynamic so new articles appear immediately export const dynamic = 'force-dynamic' // OR: revalidate every 60s (ISR — recommended for large sites) // export const revalidate = 60 const BASE_URL = process.env.NEXT_PUBLIC_SITE_URL ?? 'https://yourdomain.com' // Category slugs — must match your DB/route slugs exactly const CATEGORY_SLUGS = [ 'business', 'money-markets', 'tech-innovation', 'ai', 'lifestyle', 'politics', ] export default async function sitemap(): Promise<MetadataRoute.Sitemap> { // ── 1. Fetch all published articles ─────────────────────────────── const articles = await prisma.post.findMany({ where: { status: 'PUBLISHED', deletedAt: null, }, select: { slug: true, updatedAt: true, category: { select: { slug: true } }, }, orderBy: { updatedAt: 'desc' }, }) // ── 2. Static routes (highest priority) ─────────────────────────── const staticRoutes: MetadataRoute.Sitemap = [ { url: `${BASE_URL}/`, lastModified: new Date(), changeFrequency: 'hourly', // homepage updates constantly priority: 1.0, }, { url: `${BASE_URL}/latest`, lastModified: new Date(), changeFrequency: 'hourly', priority: 0.9, }, { url: `${BASE_URL}/about`, lastModified: new Date('2025-01-01'), changeFrequency: 'yearly', priority: 0.4, }, { url: `${BASE_URL}/contact`, lastModified: new Date('2025-01-01'), changeFrequency: 'yearly', priority: 0.3, }, ] // ── 3. Category pages ───────────────────────────────────────────── const categoryRoutes: MetadataRoute.Sitemap = CATEGORY_SLUGS.map((slug) => ({ url: `${BASE_URL}/category/${slug}`, lastModified: new Date(), changeFrequency: 'hourly' as const, priority: 0.8, })) // ── 4. Article pages ────────────────────────────────────────────── const articleRoutes: MetadataRoute.Sitemap = articles.map((article) => ({ url: `${BASE_URL}/article/${article.slug}`, lastModified: article.updatedAt, changeFrequency: 'weekly' as const, priority: 0.7, })) return [...staticRoutes, ...categoryRoutes, ...articleRoutes] }
  • Output URL: /sitemap.xml — served automatically by Next.js, no redirect needed.
  • force-dynamic ensures every crawl gets the freshest slug list. Use revalidate = 60 for sites with 1000+ articles to reduce DB load.
  • priority is a hint, not a guarantee. Google may ignore it. Set it anyway — Bing and others respect it.
  • lastModified is the most important field Google reads. Use real updatedAt timestamps from the DB, not hardcoded dates.
  • changeFrequency for articles: use 'weekly' not 'daily' — articles rarely change after publication and overclaiming causes crawl wasted visits.
Advanced10,000+ URLs
Sitemap Index — For Large Sites (10,000+ articles)
Google's sitemap limit is 50,000 URLs or 50 MB per file. For large news sites, use a sitemap index that splits articles by category or date. Next.js supports this via app/sitemap/[id]/route.ts.
app/sitemap/[id]/route.ts — individual shard
import { NextResponse } from 'next/server' import { prisma } from '@/lib/prisma' const BASE_URL = process.env.NEXT_PUBLIC_SITE_URL! const PAGE_SIZE = 1000 export async function GET(_: Request, { params }: { params: { id: string } }) { const page = Number(params.id) const articles = await prisma.post.findMany({ where: { status: 'PUBLISHED', deletedAt: null }, select: { slug: true, updatedAt: true }, skip: (page - 1) * PAGE_SIZE, take: PAGE_SIZE, orderBy: { updatedAt: 'desc' }, }) const xml = `<?xml version="1.0" encoding="UTF-8"?> <urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9"> ${articles.map((a) => ` <url> <loc>${BASE_URL}/article/${a.slug}</loc> <lastmod>${a.updatedAt.toISOString()}</lastmod> <changefreq>weekly</changefreq> <priority>0.7</priority> </url>`).join('\n')} </urlset>` return new NextResponse(xml, { headers: { 'Content-Type': 'application/xml; charset=utf-8', 'Cache-Control': 'public, s-maxage=3600, stale-while-revalidate=86400', }, }) }

app/news-sitemap.xml/route.ts — Google News Sitemap
News publishers should submit a separate Google News Sitemap alongside the regular sitemap. It uses the news: namespace and covers only articles published in the last 48 hours. This is the primary signal for Google News / Discover inclusion.
Google News Sitemap Rules (2026)
Only include articles published in the past 48 hours. Max 1,000 URLs. Do not include the same URL in both the news sitemap and the regular sitemap on the same submission. Submit the news sitemap URL separately in Google Search Console under "Sitemaps".
app/news-sitemap.xml/route.ts
import { NextResponse } from 'next/server' import { prisma } from '@/lib/prisma' export const dynamic = 'force-dynamic' const BASE_URL = process.env.NEXT_PUBLIC_SITE_URL! const PUBLICATION_NAME = 'Newsroom' // must match Search Console verification const PUBLICATION_LANG = 'en' export async function GET() { const cutoff = new Date(Date.now() - 48 * 60 * 60 * 1000) // 48 hours ago const articles = await prisma.post.findMany({ where: { status: 'PUBLISHED', deletedAt: null, createdAt: { gte: cutoff }, }, select: { slug: true, title: true, createdAt: true, }, orderBy: { createdAt: 'desc' }, take: 1000, }) const xml = `<?xml version="1.0" encoding="UTF-8"?> <urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9" xmlns:news="http://www.google.com/schemas/sitemap-news/0.9"> ${articles.map((a) => ` <url> <loc>${BASE_URL}/article/${a.slug}</loc> <news:news> <news:publication> <news:name>${PUBLICATION_NAME}</news:name> <news:language>${PUBLICATION_LANG}</news:language> </news:publication> <news:publication_date>${a.createdAt.toISOString()}</news:publication_date> <news:title>${a.title.replace(/&/g, '&amp;').replace(/</g, '&lt;')}</news:title> </news:news> </url>`).join('\n')} </urlset>` return new NextResponse(xml, { headers: { 'Content-Type': 'application/xml; charset=utf-8', 'Cache-Control': 'public, s-maxage=300, stale-while-revalidate=600', }, }) }

Priority & Change Frequency Reference

Route Priority changeFrequency Rationale
/ 1.0 hourly Homepage is the single highest-value URL. Refreshes constantly.
/latest 0.9 hourly Aggregator view — changes with every new publish.
/category/[slug] 0.8 hourly Category index pages are key landing pages for topic searches.
/article/[slug] 0.7 weekly Individual articles rarely change. Overclaiming "daily" wastes crawl budget.
/about 0.4 yearly Static page, very low crawl value.
/contact 0.3 yearly Static, low value. Include for completeness, not for ranking.
/search?q=... EXCLUDE — Search result pages have noindex. Never include in sitemap.
/dashboard/* EXCLUDE — Auth-protected. Must be blocked in robots.txt AND excluded from sitemap.
/admin/* EXCLUDE — Same — admin routes must never appear in any sitemap.
§ 03 — robots.txt — Dynamic App Router
app/robots.ts vs /public/robots.txt
Use app/robots.ts (typed, dynamic) instead of a static file in /public. The typed approach is validated by TypeScript, automatically picks up your NEXT_PUBLIC_SITE_URL env var, and prevents the #1 mistake: hardcoding the wrong domain in production.
app/robots.tsPrimary
app/robots.ts — Full Implementation
Serves at /robots.txt automatically. The MetadataRoute.Robots type enforces correct shape. Sitemap URL is injected from env var so it's always correct across environments.
app/robots.ts
import { MetadataRoute } from 'next' const BASE_URL = process.env.NEXT_PUBLIC_SITE_URL ?? 'https://yourdomain.com' export default function robots(): MetadataRoute.Robots { return { rules: [ // ── Primary rule for all crawlers ────────────────────────────── { userAgent: '*', allow: [ '/', '/article/', '/category/', '/latest', '/about', '/contact', ], disallow: [ '/admin', // CMS — never index '/admin/', '/dashboard', // User private area '/dashboard/', '/auth/', // Login/register/reset pages '/api/', // All API endpoints — no HTML value '/search', // Dynamic search results — noindex anyway '/_next/', // Next.js internals — never crawl '/cdn-cgi/', // Cloudflare/CDN internals if present ], }, // ── Block known bad bots explicitly ──────────────────────────── // Bots that ignore robots.txt won't respect this, but it's // a useful signal and some crawlers do honor it. { userAgent: [ 'AhrefsBot', // Major SEO crawler — allow if you want backlink data 'SemrushBot', 'DotBot', 'MJ12bot', ], disallow: ['/'], // Block entirely to save crawl bandwidth }, // ── AI training crawlers — block (2026 standard practice) ────── { userAgent: [ 'GPTBot', // OpenAI 'ChatGPT-User', 'Google-Extended', // Google AI training (separate from Googlebot) 'ClaudeBot', // Anthropic crawler 'CCBot', // Common Crawl (used in AI training) 'anthropic-ai', 'Omgilibot', 'FacebookBot', 'Bytespider', // TikTok/ByteDance 'PetalBot', 'cohere-ai', ], disallow: ['/'], }, // ── Googlebot: explicit allow for good measure ───────────────── // Google reads robots.txt very literally — being explicit helps. { userAgent: 'Googlebot', allow: ['/'], disallow: [ '/admin', '/dashboard', '/auth/', '/api/', '/_next/', ], crawlDelay: 1, // 1 second between requests — polite }, ], // Sitemap URLs — always include both if using Google News sitemap sitemap: [ `${BASE_URL}/sitemap.xml`, `${BASE_URL}/news-sitemap.xml`, // Remove if not a news publisher ], // Host directive (some crawlers use this) host: BASE_URL, } }
  • The host field is recognized by Yandex and some others — always set it to your canonical domain.
  • Blocking /api/ prevents API responses from appearing in search results (which they sometimes do without this).
  • Blocking /_next/ prevents Next.js chunk files, source maps, and internal routes from being indexed.
  • AI crawler blocks are now standard editorial practice in 2026. Adjust based on your publication's policy.
  • The crawlDelay on Googlebot is optional but polite. Google recommends not setting it lower than 1.

§ 04 — Google 2026 — What Actually Matters
Core signal changes in 2026
Google's 2025–2026 core updates de-weighted thin content and amplified E-E-A-T (Experience, Expertise, Authoritativeness, Trustworthiness) signals. For a news site, this means author attribution schema, organizational schema, and freshness signals via lastModified are more important than ever.
generateMetadata() — Per-Article SEO (Critical)
Every article page must export generateMetadata(). This is more important than the sitemap — it controls what Google, Twitter Cards, and Open Graph show in search results and social previews.
app/article/[slug]/page.tsx — generateMetadata
import { Metadata } from 'next' import { prisma } from '@/lib/prisma' import { notFound } from 'next/navigation' const BASE_URL = process.env.NEXT_PUBLIC_SITE_URL! export async function generateMetadata({ params, }: { params: { slug: string } }): Promise<Metadata> { const article = await prisma.post.findUnique({ where: { slug: params.slug, status: 'PUBLISHED', deletedAt: null }, include: { author: true, category: true }, }) if (!article) notFound() const url = `${BASE_URL}/article/${article.slug}` const ogImage = article.coverImage ?? `${BASE_URL}/og-default.jpg` return { title: article.title, description: article.excerpt ?? article.title, authors: [{ name: article.author.name, url: `${BASE_URL}/author/${article.author.id}` }], // Canonical URL — prevents duplicate content issues alternates: { canonical: url }, // Open Graph — controls social previews openGraph: { type: 'article', url: url, title: article.title, description: article.excerpt ?? article.title, images: [{ url: ogImage, width: 1200, height: 630, alt: article.title }], publishedTime: article.createdAt.toISOString(), modifiedTime: article.updatedAt.toISOString(), authors: [article.author.name], section: article.category.name, tags: [article.category.slug], siteName: 'Newsroom', locale: 'en_US', }, // Twitter Cards twitter: { card: 'summary_large_image', title: article.title, description: article.excerpt ?? article.title, images: [ogImage], }, // Robots — index all published articles robots: { index: true, follow: true, googleBot: { index: true, follow: true, 'max-image-preview': 'large', // required for Google Discover image previews 'max-snippet': -1, // allow any snippet length 'max-video-preview': -1, }, }, } }
JSON-LD — NewsArticle Schema (E-E-A-T Signal)
Structured data is a direct E-E-A-T signal. NewsArticle schema tells Google this is journalism, not a blog post. Always include author name and organization. Never inject JSON-LD via client-side effect — it must be server-rendered.
components/ArticleJsonLd.tsx — server component
interface Props { title: string description: string image: string slug: string authorName: string publishedAt: Date updatedAt: Date categoryName:string } const BASE_URL = process.env.NEXT_PUBLIC_SITE_URL! export function ArticleJsonLd({ title, description, image, slug, authorName, publishedAt, updatedAt, categoryName }: Props) { const jsonLd = { '@context': 'https://schema.org', '@type': 'NewsArticle', headline: title, description: description, image: [image], url: `${BASE_URL}/article/${slug}`, datePublished: publishedAt.toISOString(), dateModified: updatedAt.toISOString(), inLanguage: 'en-US', author: { '@type': 'Person', name: authorName, }, publisher: { '@type': 'NewsMediaOrganization', name: 'Newsroom', logo: `${BASE_URL}/logo.png`, url: BASE_URL, }, articleSection: categoryName, isPartOf: { '@type': 'WebSite', url: BASE_URL, name: 'Newsroom', }, // 2026: speakable tells Google Assistant which text to read aloud speakable: { '@type': 'SpeakableSpecification', cssSelector: ['.article-headline', '.article-deck'], }, } return ( <script type="application/ld+json" dangerouslySetInnerHTML={{ __html: JSON.stringify(jsonLd) }} /> ) }
ISR Revalidation Webhook — Keep Sitemap Fresh on Publish
When an article is published, call this webhook to purge the sitemap cache. Otherwise the sitemap is stale until the next natural revalidation window. Trigger this from your CMS save Server Action or admin post-creation flow.
app/api/revalidate/route.ts
import { revalidatePath, revalidateTag } from 'next/cache' import { NextRequest, NextResponse } from 'next/server' export async function POST(req: NextRequest) { const secret = req.headers.get('x-revalidate-secret') if (secret !== process.env.REVALIDATE_SECRET) { return NextResponse.json({ error: 'Unauthorized' }, { status: 401 }) } const { slug, categorySlug } = await req.json() // Revalidate the new article page if (slug) revalidatePath(`/article/${slug}`) // Revalidate the category it belongs to if (categorySlug) revalidatePath(`/category/${categorySlug}`) // Revalidate global pages revalidatePath('/') revalidatePath('/latest') // Revalidate the sitemap so Googlebot gets fresh URLs on next crawl revalidatePath('/sitemap.xml') return NextResponse.json({ revalidated: true, ts: new Date().toISOString() }) }
Search Console Setup — Submit Sitemaps
01
Verify ownership via DNS TXT record
In Google Search Console → Add property → Domain → Copy the TXT record value. Add it to your domain's DNS at the registrar. Fastest verification method — no file uploads needed.
02
Submit sitemap.xml
Sitemaps → Add a new sitemap → Enter sitemap.xml. Google will fetch and process it within hours. Status should show "Success".
03
Submit news-sitemap.xml separately
Same as above — enter news-sitemap.xml as a second sitemap. Google News uses a separate processing pipeline for the news namespace.
04
Monitor Index Coverage report
URL Inspection → Coverage. Watch for "Crawled – currently not indexed" (content quality issue) vs. "Discovered – currently not indexed" (crawl budget issue). The sitemap helps with the latter.
05
Check robots.txt in Search Console
Settings → robots.txt Tester. Paste any URL and verify it returns "Allowed" or "Blocked" as expected. Always test /admin/ (must be Blocked) and /article/test-slug (must be Allowed).
§ 05 — Common SEO Errors & Fixes
Symptom / Error Root Cause Fix
Sitemap not found Using static /public/sitemap.xml but Next.js App Router overrides it, or app/sitemap.ts has a TypeScript error and silently fails. Run npm run build locally — check for TS errors in sitemap.ts. Visit /sitemap.xml in the browser and confirm valid XML is returned.
sitemap.xml returns 500 Prisma call in sitemap.ts throws at build time (DB not reachable) or at runtime (connection error). Wrap Prisma call in try/catch and return an empty array on error so the sitemap file itself never 500s. Log the error separately.
Admin routes indexed by Google /admin missing from robots.ts disallow list, or noindex meta tag not set on admin layout. Add to both: robots.ts disallow AND app/admin/layout.tsx metadata robots: { index: false, follow: false }. Defense in depth.
Search result pages indexed /search not blocked in robots.txt, and noindex metadata missing from search page. Add /search to disallow in robots.ts. In app/search/page.tsx: export const metadata = { robots: { index: false } }.
Duplicate content — www vs non-www Site resolves on both www.domain.com and domain.com without canonical. Set canonical in generateMetadata for every page. Configure Netlify redirect: all www.* → apex domain (or vice versa) with 301 in netlify.toml.
lastModified always "now" Using new Date() for lastModified on article routes instead of real updatedAt from DB. Always use the actual updatedAt timestamp from the database. Google uses this to decide whether to re-crawl. Stale-but-unchanged articles should not trigger re-crawls.
NEXT_PUBLIC_SITE_URL wrong in sitemap Env var not set in Netlify, defaulting to localhost:3000 in produced sitemap. Add NEXT_PUBLIC_SITE_URL=https://yourdomain.com in Netlify Dashboard → Site configuration → Environment variables. Scope to Production.
OG image 400 error Cloudinary hostname not in next.config.js remotePatterns, causing Next.js image optimization to refuse the URL. Add res.cloudinary.com to remotePatterns. For OG images, use absolute Cloudinary CDN URLs directly (bypass next/image optimization for OG).
Google Discover won't show images Missing 'max-image-preview': 'large' in googleBot robots metadata. Google Discover requires explicit permission for large image previews. Add to generateMetadata(): robots: { googleBot: { 'max-image-preview': 'large' } }. Required for Discover inclusion.
Sitemap URL wrong environment Sitemap generated during Netlify build preview (deploy preview URL) but submitted to Search Console with production URL. Always use NEXT_PUBLIC_SITE_URL (set to production domain) for sitemap URL construction. Do not use Netlify's auto-injected URL env var in the sitemap.
§ 06 — SEO Pre-Launch Checklist
Pre-DeployAll Must Pass
Complete SEO Checklist — sitemap + robots + metadata
  • DO app/sitemap.ts exists, exports a default async function returning MetadataRoute.Sitemap.
  • DO app/robots.ts exists, exports a default function returning MetadataRoute.Robots.
  • DO NEXT_PUBLIC_SITE_URL is set in Netlify env vars to the exact production domain (no trailing slash).
  • DO Visit /sitemap.xml in browser — confirm valid XML with real article URLs, not localhost.
  • DO Visit /robots.txt in browser — confirm /admin, /dashboard, /auth/, /api/ are all in Disallow.
  • DO Visit /robots.txt — confirm Sitemap: line points to the correct production URL.
  • DO Test in Google Search Console → robots.txt Tester: /admin/posts must return "Blocked".
  • DO Test in Google Search Console → robots.txt Tester: /article/test-slug must return "Allowed".
  • DO Every article/[slug]/page.tsx exports generateMetadata() with real title, description, OG image, canonical URL.
  • DO OG images are 1200×630 px. Test with Facebook Debugger and Twitter Card Validator.
  • DO NewsArticle JSON-LD is server-rendered on every article page. Validate at validator.schema.org.
  • DO max-image-preview: large is set in googleBot robots metadata for article pages.
  • DO Sitemap submitted to Google Search Console — status shows "Success", not "Couldn't fetch".
  • DO News sitemap submitted separately if you are a news publisher (under 48-hour article cutoff logic).
  • DO /search has robots: { index: false } in its metadata AND is in the robots.txt disallow list.
  • DO Admin and dashboard layouts have robots: { index: false, follow: false } as defense-in-depth.
  • DO sitemap.ts Prisma call is wrapped in try/catch — sitemap must never 500.
  • CHECK changeFrequency: 'daily' on articles? Change to 'weekly' — overclaiming wastes crawl budget.
  • CHECK Are draft or soft-deleted posts leaking into the sitemap? Ensure status: 'PUBLISHED' and deletedAt: null filters are present.
  • NEVER Include /search?q=... URLs in the sitemap — these are noindex and will cause crawl budget waste.
  • NEVER Include /dashboard or /admin URLs in any sitemap — ever.
  • NEVER Hardcode localhost:3000 as the base URL in sitemap.ts without a fallback — always use NEXT_PUBLIC_SITE_URL.
  • NEVER Use a static /public/sitemap.xml file alongside app/sitemap.ts — the static file wins and your dynamic one is never served.
