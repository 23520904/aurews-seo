§ 01 — Responsive Rules

Breakpoints & Layout Rules

Every CSS rule that governs how NEWSROOM adapts from 320px feature phones to 1440px wide-screen monitors. Mobile-first cascade — define the smallest viewport, override upward.

Breakpoint Scale

Mobile-First Cascade Rule

Write base styles for XS (0px) first. Use min-width media queries to override upward. Never use max-width for layout — it creates specificity conflicts and negates mobile-first intent. The exception is the utility bar text-hide at max-width: 479px which is a cosmetic trim, not a structural rule.

Component-Level Responsive Rules

Layout

Wrapper + Container

Always use max-width: 1440px with margin-inline: auto. Padding scales via CSS variable per breakpoint. Never use fixed pixel widths on containers — use width: 100% inside the wrapper.

Grid

CSS Grid — Story Tiles

Default: 1fr. At 600px: 1fr 1fr. At 1024px: 1fr 1fr 1fr. At 1280px wide grids get a 4th column. Use gap tokens, never margin hacks between grid children.

Navigation

Nav — Mobile Drawer

Below 768px: hamburger + slide drawer. The drawer uses aria-expanded, traps focus, and closes on ESC. Section nav strip is hidden on mobile — category links live in the drawer instead.

Sticky

Sticky Header

Masthead uses position: sticky; top: 0; z-index: 100. This provides persistent orientation — a core UX principle. Background must be opaque (background: var(--paper)) or content scrolls under it visibly.

Tables

Table Overflow

Wrap every <table> in overflow-x: auto; -webkit-overflow-scrolling: touch. Set min-width on the table itself (e.g. 640px) to prevent text collapse. Add tabindex="0" for keyboard scrolling.

Code

Code Block Overflow

Code blocks use overflow-x: auto; white-space: pre; max-width: 100%. On mobile they become horizontally scrollable rather than wrapping, preserving code structure. Never use white-space: pre-wrap — it breaks indentation.

Sidebar

TOC Sidebar

Below 1024px: TOC renders above main content with a collapsible toggle. At 1024px+: TOC moves to the right column with position: sticky; top: 80px. Two-column layout switches at 1024px via CSS Grid.

Touch

Touch Targets

Every interactive element (links, buttons, inputs) must have a minimum tap area of 44×44px per WCAG 2.5.5. Use padding to expand the target without changing visual size. Drawer nav links use min-height: 44px; display: flex; align-items: center.

Forms

Responsive Inputs

Newsletter form: input + button stacked on XS, inline on SM+. Input width: 100% on mobile. On desktop: display: flex; gap: 0 with button attached. Never use font-size < 16px on inputs — iOS Safari zooms on focus below 16px.

Use clamp(min, preferred, max) for headings. The preferred value is a viewport unit that scales smoothly between breakpoints. No step-function jumps.

§ 02 — SEO Optimization
Search Engine Optimization

SEO Rules — Every Layer

From HTML <head> meta tags through JSON-LD structured data, sitemap configuration, and Core Web Vitals. Each rule maps to a ranking signal.

Head Meta — Every Page Must Have

title
60–65 chars. Format: Article Title — NEWSROOM. Primary keyword first. Never duplicate across pages. Generated by generateMetadata() per route.
meta description
120–158 chars. Summarize the page value proposition. Include primary keyword naturally. Used as snippet in SERPs. Not a ranking factor but drives CTR.
canonical
<link rel="canonical" href="..."> on every page. Prevents duplicate content penalties from URL parameters, trailing slashes, or pagination variants.
robots
index, follow on all public pages. noindex on /admin, /dashboard, /search, /auth/*. Set via Next.js metadata.robots export.
og:title + og:description
Open Graph tags for social sharing previews. og:title can differ from <title> — make it more conversational for social. Required for Facebook, LinkedIn.
og:image
1200×630px minimum. Include og:image:width and og:image:height. Use Cloudinary for on-demand OG image generation. Without this, platforms pick a random image.
twitter:card
summary_large_image for articles (full-width preview). summary for utility pages. Always set even if you don't use X/Twitter — it affects other platforms too.
lang attribute
<html lang="en"> — or the correct BCP 47 code. Google uses this for language targeting. Screen readers use it for pronunciation. Missing = SEO and a11y fail.
charset + viewport
<meta charset="UTF-8"> must be the first tag in <head>. <meta name="viewport" content="width=device-width, initial-scale=1.0"> is required for mobile-first indexing.
preconnect
<link rel="preconnect" href="https://fonts.googleapis.com"> for any external origin used in the critical path. Reduces DNS + TCP + TLS latency for LCP resources.
article:published_time
On article pages: og:type="article", article:published_time, article:modified_time, article:section. Enables Google News freshness signals.
hreflang
If serving multiple languages or regions: <link rel="alternate" hreflang="...">. Use x-default for the fallback. Missing hreflang causes duplicate content across locales.
JSON-LDStructured Data
JSON-LD Schema — By Page Type
Inject via <Script type="application/ld+json"> server-side in Next.js layout or page. Do NOT use Microdata or RDFa — JSON-LD is Google's preferred format and is decoupled from HTML structure.

Core Web Vitals — Targets & Fixes

LCP < 2.5s
Hero image: priority={true} on next/image injects <link rel="preload">. Serve from Netlify CDN edge. Avoid above-the-fold CSS background images — use <img> so preload can find it.
CLS < 0.1
All next/image must declare width + height — reserves space before image loads. Use next/font with display: swap for zero font-induced layout shift. No aspect-ratio CSS hacks needed.
INP < 200ms
Heavy components (TipTap editor) use dynamic(import, {ssr:false}). Load More uses useTransition to keep UI responsive during fetch. No synchronous localStorage reads in render path.
TTFB < 800ms
Homepage + category pages use ISR (revalidate 60s). Static assets served from CDN. Database queries use Prisma connection pooling via PgBouncer to eliminate cold-start DB latency.
FCP < 1.8s
Inline critical CSS for above-the-fold content. Preconnect to Google Fonts. font-display: swap prevents invisible text during font load. No render-blocking scripts in <head>.
Accessibility Score
Google uses a11y as a ranking signal. Semantic HTML, ARIA labels, colour contrast ≥ 4.5:1 (black on white = 21:1 ✓), skip link, focus indicators. Run Lighthouse on every deploy.
§ 03 — UX/UI Design Principles
User Experience & Interface Design

The 12 UX/UI Principles Applied to NEWSROOM

Every principle below is implemented in CSS, component logic, or content structure — not aspirational theory. Each maps to a concrete rule in the codebase.

01

Hierarchy — The Eye Follows Type Weight, Not Color

WIRED's design achieves hierarchy with size and ink alone. Hero headline at clamp(1.625rem, 1rem + 3.5vw, 4rem). Grid headlines at clamp(1.125rem, 0.85rem + 1.4vw, 1.625rem). Kickers at 0.72rem mono. Color never signals importance — only grayscale + blue for links. This forces readers' eyes down the intended path without distraction.

02

Progressive Disclosure — Show Less, Reveal More

Category pages load 12 posts. "LOAD MORE" reveals 8 more via cursor pagination using useTransition — never a full page reload. The TOC on mobile is collapsed by default — one tap reveals all sections. The admin accordion in the API docs hides child details until needed. Each disclosure removes cognitive load from the initial view.

03

Feedback — Every Action Has a Response

Buttons animate on hover: background/color transition: 150ms. Links animate: color transition: 120ms. The scroll progress bar gives continuous reading progress feedback. Forms show toast on newsletter signup success. The hamburger icon transforms (3 bars → X) on open. Feedback latency under 200ms is invisible; over 500ms is friction.

04

Consistency — Same Pattern, Same Result, Everywhere

The mono kicker pattern appears above every story headline across homepage, category pages, article page, and search results. The ribbon header appears before every module section. Black → white button inversion is the same behavior on every button. If a user learns one pattern, they've learned all instances. Inconsistency forces re-learning and erodes trust.

05

Affordance — Things That Look Clickable Are Clickable

Buttons have 2px solid #000000 borders — they look like physical buttons, not flat text. Links in body copy have text-decoration: underline at all times (not just hover). Nav items underline on hover. Round icon buttons suggest rotational actions. No element fakes affordance without being interactive — a cardinal sin of flat design overreach.

06

Orientation — The User Always Knows Where They Are

Sticky header persists at all scroll depths. Active section nav link is underlined with border-bottom: 2px solid var(--black). Scroll progress bar reads 0–100%. Breadcrumb JSON-LD signals position in site hierarchy. TOC highlights the current section (implementable with IntersectionObserver). Every page has a unique, descriptive <h1>. Users should never ask "where am I?"

07

Cognitive Load — Reduce the Number of Decisions Per Screen

The color palette has exactly two functional colors: black (ink/structure) and #057dbc (links/interactive). Adding a third color forces users to decode meaning. Story tiles show three pieces of information: kicker, headline, byline — not five. Mobile nav hides category sub-nav until the drawer opens. Whitespace between sections is not decoration — it's a pause that reduces processing load.

08

Error Prevention — Validate Before Submit, Not After

Registration form checks email uniqueness on blur (server-side, 409 response) before form submission. Newsletter form shows inline validation before calling the Server Action. Contact form has a honeypot field. Password fields use browser-native type validation. CSRF tokens (NextAuth) prevent cross-site POST. Rate limiting at the edge prevents spam before it reaches the DB. Catch errors before they become user-visible failures.

09

Speed Perception — Perceived Performance > Actual Performance

Optimistic UI: "LOAD MORE" adds items to the list before the fetch confirms. Skeleton loaders (height-matched placeholders) prevent CLS and signal content is coming. The loading="lazy" attribute on below-fold images prevents bandwidth waste. priority={true} on the hero image makes the first visible thing load first. A page that feels fast converts better than one that is fast but looks slow.

10

Scannability — Readers Don't Read, They Scan

Every section has a mono ALL-CAPS kicker, a display headline, and an optional deck — the F-pattern hierarchy. "Most Popular" uses 40px numerals as anchors. Hairline rules separate stories without requiring the eye to decode spatial distance. Bold is rare (Apercu 700 only for UI) so when it appears, it genuinely signals importance. Reading time estimate above the byline lets readers self-select before committing.

11

Mobile Context — Thumb Zones & Touch Intent

Primary CTA buttons are positioned in the natural thumb zone on mobile (bottom-center or full-width). Nav links in the drawer use min-height: 44px. Form inputs use font-size: 16px to prevent iOS auto-zoom. Swipeable horizontal scrolls (category strip) have -webkit-overflow-scrolling: touch and hide scrollbars. The hero image is full-width (no margin compression) on XS — screens are small, make images count.

12

Forgiveness — Let Users Undo & Recover

The post editor auto-saves to localStorage every 30 seconds — surviving page refreshes. Delete actions require a confirmation modal (inline, not a native browser confirm()). Admin soft-deletes posts (sets deletedAt) rather than permanently removing them. Password reset uses a single-use, hashed, time-limited token. Users who make mistakes should have a clear, fast path back.

§ 04 — Responsive Typography
Typography Rules

Type Scale & Responsive Rules

The four typefaces each have exactly one job. These rules prevent role-swapping and ensure the design system survives responsive collapse.

WiredDisplay → Playfair

Display / Hero Headlines

Only for hero headlines and major section titles. clamp() from 26px to 64px. Letter-spacing: -0.5px at large sizes. Line-height: 1.05 at 64px (tight for print feel). Never use for body, UI, or kickers.

BreveText → Lora

Body / Deck / Long-form

Article body at 16px / 1.7 line-height. Decks at 19px / 1.47. Captions at 12.73px / 2.20 (generous leading for print-photo feel). Max-width: 65ch on article body — optimal reading line length.

Apercu → Work Sans

UI Labels / Buttons / Nav

Buttons, nav items, section headings, "Most Popular" numbers. Weight 700 for emphasis, 400 for secondary UI. Never lowercase in kicker position — that's WiredMono's role. Letter-spacing: 0.3px on buttons.

WiredMono → Space Mono

Kickers / Eyebrows / Labels

Always uppercase. Always 0.9–1.2px letter-spacing. 12–13px size — never scale down further or it becomes unreadable. Used for: section kickers, timestamps, ribbon labels, "X HOURS AGO". Lowercase mono = design error.

Substitution Warning — Font Metric Compensation

Playfair Display (substituting WiredDisplay) has wider metrics. Loosen hero line-height from 0.93 to approximately 1.05 to prevent ascender/descender collisions on wrapping lines. Lora and Work Sans substitute without adjustment. Space Mono substitutes without adjustment.

alt Text Rules — SEO + Accessibility

Decorative images: alt="" (empty string, not missing). Screen readers skip it. Content images: describe what the image shows, not "image of..." — e.g. alt="Protestors outside the Capitol building". Never use the filename as alt text. Never repeat the caption as alt text. Google uses alt text as an image ranking signal for Google Images.

§ 06 — Performance Rules
Performance Optimization

Zero-Bloat Performance

SSG + ISR

Rendering Strategy Per Route

  • Homepage, categories: ISR (60s revalidate). Fastest possible TTFB from CDN.
  • Article pages: ISR (on-demand via webhook). Near-static speed with fresh content.
  • Dashboard, admin: SSR with force-dynamic. Must be session-fresh.
  • Search: SSR. Query-dependent, can't be cached.
  • Static pages (About, Contact): export const dynamic = 'force-static' — pure CDN.
Bundle

Bundle Size Rules

  • TipTap editor: dynamic(import, {ssr:false}) — never in initial bundle.
  • Date-fns: import individual functions, not the full library.
  • No lodash full import — use lodash/get etc.
  • Run npx @next/bundle-analyzer monthly. Target <200kb first-load JS.
  • Use next/dynamic for any component >50kb that's not above-the-fold.
Cache

Cache Headers

  • /_next/static/*: public, max-age=31536000, immutable. Hashed filenames guarantee freshness.
  • /api/*: no-store, no-cache, must-revalidate. API responses must never be stale.
  • Cloudinary images: 1yr CDN cache. Transformations are URL-versioned.
  • HTML pages: Netlify CDN cache + stale-while-revalidate via ISR.
Fonts

Font Loading Strategy

  • Use next/font/google — self-hosted, zero layout shift, automatic preloading.
  • display: 'swap' on all fonts — text visible immediately in fallback.
  • Preconnect to fonts.googleapis.com and fonts.gstatic.com in <head>.
  • Load only the weights you use. Playfair: 400+700. Space Mono: 400+700.
§ 07 — Accessibility (WCAG AA)
Accessibility Rules

WCAG AA — Non-Negotiable Rules

Accessibility is not a separate concern — it's the foundation of good UX. Every rule here also improves SEO and keyboard usability.

1.4.3

Colour Contrast — 4.5:1 Min

Black on white = 21:1. Blue #057dbc on white = 4.6:1 (passes AA). Caption grey #757575 on white = 4.6:1. Never use #999999 for body text — 2.85:1 fails. Check every custom colour with WebAIM Contrast Checker before shipping.

2.4.1

Skip Navigation Link

<a href="#main-content" class="skip-link"> as the first element in <body>. Visually hidden until focused (top: -9999px, visible on :focus). Allows keyboard-only users to bypass repeated nav on every page.

2.4.7

Focus Indicators

:focus-visible { outline: 2px solid #057dbc; outline-offset: 2px; }. Never outline: none without a replacement. Focus indicators must be visible against all backgrounds. The 2px blue outline satisfies 3:1 contrast requirement.

1.1.1

Alt Text on Every Image

Content images: descriptive alt text. Decorative images: alt="". Icons in buttons: add aria-label to the button. The hamburger button must have aria-label="Toggle navigation" and aria-expanded state toggled via JS.

4.1.2

Semantic HTML Structure

One <h1> per page. Heading hierarchy: h1 → h2 → h3 (no skipping). <main>, <header>, <nav aria-label>, <footer>, <article>. Tables have <caption> and scope on <th>. Form inputs have associated <label> elements.

2.1.1

Full Keyboard Navigation

All interactive elements reachable via Tab. Mobile drawer: focus trap while open (first item → last item → first item). ESC closes drawer, modals, and overlays. Dropdowns navigable via arrow keys. Custom components use correct ARIA roles (role="dialog", role="navigation").

§ 08 — Pre-Launch Checklist
Quality Gate

Every Item Must Pass Before Deploy

Responsive
Responsive — Device Testing
  • TEST Open Chrome DevTools → Device Toolbar. Test: iPhone SE (375px), iPhone 14 Pro (393px), iPad mini (768px), iPad Pro (1024px), MacBook (1280px), 1440px wide. Check every page at each size.
  • TEST Horizontal scroll at 320px: no element bleeds beyond viewport width. Check with document.querySelectorAll('*') filter for scrollWidth > window.innerWidth.
  • CHECK All images maintain correct aspect ratios (no stretching) at every breakpoint. next/image with declared width+height prevents this.
  • CHECK Nav hamburger appears below 768px. Drawer opens/closes. ESC closes it. Focus trapped inside while open.
  • CHECK Section nav appears at 768px+. All links visible without truncation. Active state visible.
  • CHECK Tables scroll horizontally on mobile with visible scroll affordance. tabindex="0" allows keyboard scrolling.
  • CHECK Code blocks scroll horizontally on mobile. Text does not wrap. Border-left stripe visible at left edge.
  • CHECK Footer links wrap cleanly on XS. No link text truncation. All links remain tappable at ≥44px height.
  • VERIFY Form inputs never trigger iOS zoom (font-size ≥ 16px on all inputs). Test by focusing an input on iPhone Safari.
  • CHECK Max-width container (1440px) is centered correctly at 1600px+ viewport. No content touches screen edge.
SEO
SEO — Audit Every Page
  • RUN npx lighthouse https://yourdomain.com --output html. Target: Performance ≥90, SEO ≥100, Accessibility ≥90, Best Practices ≥90.
  • CHECK Each page has a unique <title> (max 65 chars) and <meta name="description"> (max 158 chars).
  • CHECK Each page has a <link rel="canonical"> pointing to the correct canonical URL.
  • CHECK Article pages have JSON-LD NewsArticle schema. Validate at Rich Results Test.
  • CHECK Homepage has JSON-LD WebSite with SearchAction (Sitelinks Searchbox).
  • CHECK /sitemap.xml is accessible, returns 200, and all URLs are indexed-eligible (no noindex pages in sitemap).
  • CHECK /robots.txt is accessible, returns 200. Disallows /admin, /dashboard, /api. Includes sitemap URL.
  • CHECK Every <img> has an alt attribute (descriptive or ""). Run: document.querySelectorAll('img:not([alt])') in console — must return empty NodeList.
  • CHECK All internal links use relative URLs or NEXT_PUBLIC_SITE_URL — no hardcoded staging domain in production HTML.
  • VERIFY Google Search Console: submit sitemap, check for crawl errors 48h after deploy.
  • NEVER Ship robots: noindex on public editorial pages. Check every generateMetadata() export has correct robots value.
UX/UI
UX/UI — Visual & Interaction Audit
  • CHECK Every story tile has a mono ALL-CAPS kicker above the headline. No exceptions. Missing kicker = generic blog, not NEWSROOM.
  • CHECK All images are square-cornered (border-radius: 0). Except author avatars (border-radius: 50%) and text pills (border-radius: 1920px).
  • CHECK No box-shadow on any story tile, card, or container. Search codebase: grep -r "box-shadow" src/ and verify each result is intentional (e.g. focus ring only).
  • CHECK Hover on story headline: color transitions from #1a1a1a to #057dbc in 120–150ms. Image does not scale, lift, or change opacity.
  • CHECK All primary buttons: 2px solid #000000 border, border-radius: 0, Apercu/Work Sans 700. Hover inverts to black bg + white text.
  • CHECK Scroll progress bar appears and increments correctly on article pages. Hidden on short pages (<100vh).
  • CHECK Tab through the page with keyboard only. Every interactive element reachable. Focus indicator visible at all times.
  • CHECK Sticky header stays fixed at top during scroll. Background remains opaque — content does not bleed through.
  • CHECK Color palette audit: run getComputedStyle on all elements. Only #000, #1a1a1a, #757575, #e2e8f0, #fff, #057dbc in chrome (not photography).
  • VERIFY Test with prefers-reduced-motion: reduce (Chrome DevTools → Rendering). All animations and transitions should be disabled or instant.
  • NEVER Use gradients, glass effects, blurs, or drop shadows anywhere in the UI layer. These break the printerly contract of the WIRED design system.
Accessibility
Accessibility — WCAG AA Gate
  • RUN axe DevTools browser extension on every page template. Zero critical violations before deploy.
  • TEST Navigate entire site with keyboard only (Tab, Shift+Tab, Enter, Space, ESC). Every action completable.
  • TEST Run NVDA (Windows) or VoiceOver (Mac) on article page. Headings announce correctly. Images announce alt text. Table headers read before cells.
  • CHECK <html lang="en"> present. If multi-language: correct BCP 47 codes on each page.
  • CHECK One <h1> per page. Heading levels don't skip (no h2 → h4).
  • CHECK All form inputs have associated <label> elements (not just placeholder text).
  • CHECK All modals and dialogs trap focus and restore focus to trigger on close.
  • VERIFY WebAIM contrast checker: every foreground/background combination ≥4.5:1 for normal text, ≥3:1 for large text (18px+ regular or 14px+ bold).
